# TS06 board viewer v2: the source of the product page

The page "TS06 Board Viewer v2": a three.js viewer of the boards, the case and the fascia, a build and bring-up
stepper, the circuit sections, the front panel view, and the **Order** view. This folder is its whole source. A fresh
clone and one command build it; nothing is read from a session's scratch folder any more.

```
bash recovered/viewer2/build.sh                    # builds recovered/viewer2/site/ (git-ignored), about 2 minutes
OUT=/some/dir bash recovered/viewer2/build.sh      # builds into /some/dir/site instead, nothing written in the checkout
node recovered/viewer2/test/run.mjs                # the Playwright checks (SITE=... if you built elsewhere)
```

A fresh clone needs the npm registry once, for gltfpack (`npm install` writes `tools/node_modules` on the first run), unless `GLTFPACK=path` points to a local copy.

**Nothing here publishes.** `build.sh` writes a folder and a list of its files (`publish-files.json`, beside `site/`:
every path mapped to itself); putting the folder on a host is a separate step, and the owner's.

## What the build reads, and where it gets each input

| Input | Where it comes from | Before |
|---|---|---|
| The boards (tracks, parts, DRC) | `PCB/TS06-*/*.kicad_pcb`, read only; KiCad 10 in Docker (`mirror.gcr.io/kicad/kicad:10.0`; `nohup dockerd >/dev/null 2>&1 &` if it is down) | same |
| 3D models, `MODELS` | `3d/populated/kicad3d/` (the 29 library files the boards use, CC-BY-SA 4.0 with KiCad's exception) | `../3dmodels`, a scratch folder |
| The populated boards: GLBs and pictures | `3d/populated/TS06-DRV, TS06-DISP, TS06-FASCIA-rhythm` `-populated.glb`, `-top/iso/bottom.png`, `TS06-stack-front/iso.png` (made by `tools/populated_all.sh`; its README) | not on the page: bare KiCad exports and stand-in bodies |
| Schematic sections, `SCH` | regenerated by `tools/mksections.sh` into the work folder: KiCad's own `sch export svg` of every sheet, then the repo's `tools/mksch_pair.py --svg-out` and `tools/highlight_pair.py` (the section texts, parts and nets come from `tools/ts06pair.py`). About 15 s, 10.7 MB (SVG and PNG only), **not committed**. `SCH=DIR` still uses a folder you give | `../sch/out`, a scratch folder |
| The Order view | `tools/order.py`: `fab/ORDER.md` (the three zips, the DFM table, the open choices, what the prototype closes), the zips' sizes on disk, `3d/populated/fit-table.json` | new |
| The case, the assembly frame, the fascia positions | `3d/case-pair/out/*.stl`, and `3d/case-pair/case_pair.py` imported read-only | same |
| three.js | the page loads r186 from the CDN (jsDelivr); the tests answer those requests from `3d/populated/stack/vendor/three` (the same files, with the four addons the page needs) | `work/three`, a scratch folder |
| gltfpack 1.3.0 | `tools/node_modules/.bin/gltfpack`: `npm install` writes it on the first run (the one step that needs the npm registry, or a warm npm cache); `GLTFPACK=path` to use a binary you have | same |

Python 3 (Pillow, if present, trims the renders' margins; `tools/populated.py` imports the repository's own `tools/model_coverage.py`), Docker,
node with Playwright for the tests (`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`, browsers already installed).

## The populated boards on the page

TS06-DRV, TS06-DISP and the fascia R are drawn with every component, from the GLBs of `3d/populated/` (the models
that were missing in the Docker image are in `3d/populated/kicad3d`, `3d/populated/models` and `tools/models3d.json`). The
fascia is **R as it is ordered**: the Plates white print and the Divider gold (`3d/populated/README.md`).

* The host serves no `.glb`, so `build.sh` quantises each GLB with gltfpack (16-bit positions, named nodes kept) and embeds
  the buffer in a glTF JSON file. Sizes from the build: TS06-DRV 13.39 MiB GLB to 4.49 MB; TS06-DISP 5.71 MiB to
  1.65 MB; the fascia R 1.19 MiB to 0.30 MB (its GLB carries the copper, which is where the gold is). The largest file of the site is 4.5 MB (the host allows 15 MB a file,
  256 MB a version); `data/populated.json` records the sizes.
* On a populated board the page draws no stand-in bodies. The stepper still shows and hides parts by name (`in12`, `leds`,
  `chip:U2`, `nano`, `rtc`, `fascia`); each name now points at the part's own node in the GLB, found by its reference. A tube's socket
  contacts are part of the tube's node and a chip's socket part of the chip's, so they appear together.
* The board pictures (`img/<board>-top|iso|bottom.png`) are the populated ones, and the case pictures end with the
  populated stack (front, angled). The fascia shown first is R.
* The fascia variants A and W are not ordered and are not populated: they are drawn as before (bare KiCad body plus the
  case model's control bodies), and the facts panel says so. `POPULATED=0` draws all boards that way.
* The tracks are not in the DRV and DISP GLBs (they lie under the black mask; the files would pass 15 MB); pads, silk and mask are. The fascia R's GLB does carry its copper, because its gold is copper graphics that KiCad exports only then. The page gives the finish gold a diffuse lean, so it reads as gold and not as pale cream under its soft light.

## The glow switch

Under the camera deck of the Assembly and Display scenes (not the driver or the fascia, which have no tubes): **Numerals glow**, a switch,
**off at load**. Off, the tubes are the plain glass of the STEP files, as the populated boards are drawn. On, each tube's glass takes the page's
warm glass (`MAT.glass`, the look the stand-in tubes had) and the numeral inside it glows: the digits the stand-in tubes carried (1 to 4 on the
ИН-12, 5 and 6 on the ИН-17, A and M on the ИН-15), a plane across the tube's axis with the page's own glyph texture (`glyphTexture`:
additive orange with a soft halo). One line beside the switch says the glow is an illustration (a picture of a lit tube, not a measured one).
That glow is the one the page had before the boards were drawn populated (`buildDispProxies`, kept for the boards that are not
populated); the populated tubes' glass is opaque, so the switch turns it warm and clear as well, or the numerals could not be seen.
The setting is not kept between visits. `addGlow` and `setGlow` in `src/app.js`; the tests (`glow switch`) check it on the desktop and the
phone, light and dark.

## The Order view

A tab under the viewer ("Order"; the address `#order`). It holds, from `data/order.json`:

* what is ready, board by board: size, layers, thickness (the fascia is 2.0 mm), finish ENIG, mask and silk colour, holes,
  quantity 10, the DFM result, and the zip;
* the design-for-manufacture table, the worst value found on each board against the limit;
* the fit table's TIGHT and FAIL rows, each in plain words (`tools/order.py` writes the sentences and carries each row's own
  numbers; the table has no FAIL since the ИН-17's measured length, 19.72 mm, went in: the tube's open item is the pip, a reading);
* the open items before ordering, and what only the prototype run can close;
* where the fab zips are: links on GitHub under the branch `pcb/kicad-boards`, by their repository path
  (`fab/TS06-DISP-revB-fab.zip` ...). The zips are not embedded in the page;
* a line that placing the order is the owner's own hand. The page contacts no board house and holds no account, cart or price.

`tools/order.py` stops the build if `fab/ORDER.md` loses a table or a statement it relies on, so a rewritten sheet is noticed at
build time. Rebuild after `fab/` or the fit table changes.

## The tests

`test/run.mjs` drives the built page in Chromium (software GL: about 8 minutes in all, 158 checks; `ONLY_NEW=1` runs just the 46 checks of the
populated boards, the glow switch and the Order view, about 5 minutes). It serves `site/` on port 8766, answers the CDN's three.js from the vendored copy
and fails on any console error or request that leaves the machine. The checks cover the camera deck, the stepper, the sections, the front
panel view, light, dark and phone widths, and, for the populated boards: the files and their limits, the GLBs loaded with their
parts, no stand-in bodies, the pictures, the gold in the picture and in the 3D view, the glow switch (there, off at load, on shows the numerals, off hides them, on the desktop and the phone, light and dark) and every row of the Order view.
`SITE=`, `THREE=` and `SHOTS=` point the test at a build and a screenshot folder elsewhere.
